# download-speed-test

Консольный скрипт на Node.js для замера скорости скачивания. Делает заданное число
последовательных GET-запросов к одному адресу, полностью вычитывает тело каждого
ответа и считает среднее время запроса, суммарный объём скачанных данных и скорость.

Внешних зависимостей нет — используется только стандартная библиотека Node.js.

## Требования

- Node.js **18 или новее** (нужны встроенные `fetch` и `AbortSignal.timeout`;
  рекомендуется актуальная LTS-версия).
- Проверить версию: `node --version`.
- `npm install` не нужен.

## Запуск

```bash
git clone https://github.com/Snowxdxaxd/download-speed-test.git
cd download-speed-test

node speedtest.mjs "https://speed.cloudflare.com/__down?bytes=25000000"
```

По умолчанию выполняется 10 запросов. Число запросов и таймаут одного запроса
можно изменить:

```bash
node speedtest.mjs "https://speed.cloudflare.com/__down?bytes=25000000" --requests 3
node speedtest.mjs --requests 5 --timeout 30 "https://speed.cloudflare.com/__down?bytes=25000000"
```

Флаги можно ставить до или после URL; для параметров поддерживаются формы
`--requests 3` и `--requests=3` (аналогично для `--timeout`).

### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `<url>` | — | Адрес файла. Поддерживаются только `http://` и `https://`. |
| `-n`, `--requests N` | `10` | Число последовательных запросов, целое от 1 до 1000. |
| `--timeout SEC` | без ограничения | Таймаут одного запроса в секундах. |
| `-h`, `--help` | — | Показать справку. |

В качестве URL подойдёт любой файл по HTTP: тяжёлая картинка, архив или специальный
эндпоинт для тестов скорости. В примерах выше используется эндпоинт Cloudflare,
который генерирует 25 000 000 байт (≈ 23,84 МиБ) данных.

## Единицы измерения

| Величина | Единица | Определение |
|---|---|---|
| Время запроса | секунды (с) | От начала запроса до последнего байта тела ответа. |
| Объём данных | МиБ | 1 МиБ = 1 048 576 байт (двоичный мегабайт). |
| Скорость | Мбит/с | 1 Мбит/с = 1 000 000 бит/с (десятичный мегабит, как у провайдеров). |

Скорость считается по формуле:

```
T = t₁ + t₂ + … + tₙ          — суммарное время N запросов
среднее время запроса = T / N
скорость = (суммарные байты × 8) / T / 1 000 000
```

Время каждого запроса измеряется отдельно: от начала запроса (включая установку
соединения) до получения последнего чанка тела. Паузы между запросами (печать
в консоль и т. п.) в T не входят. Запросы выполняются строго последовательно,
поэтому они не конкурируют за канал.

#2: 0.87 с, 4.77 МиБ, 46.19 Мбит/с
#3: 0.41 с, 4.77 МиБ, 96.79 Мбит/с

Конкретные цифры зависят от канала, сервера и его загрузки. Для сравнения
результатов используйте один и тот же URL и одинаковое число запросов.

## Как это работает

1. Скрипт проверяет аргументы и URL, затем N раз последовательно делает `fetch`.
2. Тело ответа не буферизуется целиком: оно читается потоком через
   `response.body.getReader()`, а байты суммируются по мере прихода. Поэтому даже
   большой файл не занимает память целиком.
3. Таймер запроса останавливается только после последнего чанка — то есть после
   полного ответа.
4. После всех запросов печатаются среднее время, суммарный объём и скорость.

## Обработка ошибок

- Ответ с кодом вне диапазона 2xx (например, 404 или 500) — ошибка, exit code 1.
- Ошибка DNS, обрыв соединения или таймаут — ошибка, exit code 1.
- Ответ с нулевым телом считается ошибкой: на таком URL скорость не измерить.
- При ошибке на любом запросе тест останавливается, чтобы не смешивать успешные
  и неуспешные измерения.
- `--help` завершается с кодом 0, ошибки аргументов — с кодом 1.

## Замечания

- Первый запрос включает установку TCP-соединения (и TLS-рукопожатие для `https`),
  поэтому он обычно медленнее. Последующие запросы переиспользуют соединение
  (keep-alive). Это нормальное поведение: среднее время и скорость считаются по
  всем N запросам.
- Скрипт просит сервер не сжимать ответ (`Accept-Encoding: identity`), чтобы
  измерять именно скачанные данные. Если сервер всё равно сжал ответ, Node.js
  распакует его, и будут посчитаны распакованные байты.
- Замеряется пропускная способность одного последовательного потока, а не
  суммарная скорость нескольких параллельных соединений.
- Это не полноценный Speedtest: измеряется только скачивание, без upload, ping
  и jitter.
